# LocalMind

**Локальный автономный ИИ-агент на базе открытых моделей.**

LocalMind — это каркас, который превращает открытую языковую модель
(Llama, Qwen, Mistral, Gemma, Phi — любую, доступную в [Ollama](https://ollama.com))
в автономного агента, работающего целиком на вашей машине, без интернета и
без отправки данных наружу. Агент ведёт диалог, пользуется инструментами,
накапливает память, работает по целям без участия человека и — ключевая
особенность — **пишет себе новые навыки (код), расширяя собственные
возможности**.

---

## Честно о том, что это и чем не является

Обучить с нуля собственную foundation-модель уровня GPT/Claude локально
**невозможно** — это тысячи GPU и месяцы. Поэтому LocalMind делает то, что
реально работает на одном компьютере:

| Из запроса | Как реализовано в LocalMind |
|---|---|
| «новая ИИ-модель на основе открытых» | своя «личность» и поведение поверх открытых весов (Ollama) + опциональное дообучение под себя через LoRA |
| «работает локально» | вывод через локальный Ollama, ядро — только стандартная библиотека Python, ноль обязательных зависимостей, ноль сети |
| «со всеми возможностями» | диалог, вызов инструментов, исполнение кода, работа с файлами, семантическая память, зрение — если модель мультимодальна |
| «обучаемая» | постоянное обучение через RAG-память (без переобучения весов) + модуль LoRA-дообучения весов |
| «автономная, без пользователя» | цикл ReAct + режим целей `auto`, выполняющий список задач самостоятельно |
| «дополняет свои файлы и программирует новые способности» | инструмент `create_skill`: модель пишет код навыка, он проходит проверку и становится новым инструментом агента |

### Предохранители — это не ограничение, а условие безопасности
Бесконтрольный самоизменяющийся агент может испортить данные или сгенерировать
разрушительный код. Поэтому по умолчанию:
- все файловые операции и навыки заперты в **рабочей папке** (песочница путей);
- сгенерированный код проверяется на разрушительные конструкции и **исполняется в изолированном процессе с тайм-аутом**;
- новые навыки при `require_approval: true` попадают в `skills/pending/` и **активируются только после одобрения человеком**;
- произвольный shell выключен (`allow_shell: false`).

Всё это настраивается в `config.yaml` — вы сами решаете, сколько автономии дать.

## Установка

```bash
# 1. Установите Ollama:  https://ollama.com/download
ollama serve                       # поднять локальный сервер моделей

# 2. Скачайте открытую модель и модель эмбеддингов
ollama pull qwen2.5:7b-instruct    # или llama3.1, mistral, gemma2 …
ollama pull nomic-embed-text       # для семантической памяти

# 3. LocalMind зависимостей не требует. По желанию:
pip install -e .                   # установить как команду `localmind`
```

Проверка окружения:

```bash
python -m localmind doctor
```

## Быстрый старт в один клик

- **Windows:** дважды кликните `Start-LocalMind.bat` — он проверит Python и Ollama,
  поднимет сервер моделей и откроет браузерный интерфейс.
- **Linux / macOS:** `./start-localmind.sh`

Браузерный интерфейс общается только с нашим локальным сервером, а тот уже ходит
в Ollama на своей стороне — поэтому CORS и переменная `OLLAMA_ORIGINS` **не нужны**
(типовая ошибка «нет доступа к Ollama из браузера» здесь не возникает).

Запустить интерфейс вручную:

```bash
python -m localmind web            # откроет http://127.0.0.1:8770
python -m localmind web --port 9000 --no-browser
```

В интерфейсе два режима: **Чат** (обычный диалог с памятью) и **Агент** (задача
с инструментами, показывает ход рассуждений). Если Ollama не запущен — сверху
появится подсказка, и связь подхватится автоматически, как только вы выполните
`ollama serve`.

## Использование (командная строка)

```bash
# Диалог с потоковым ответом и памятью
python -m localmind chat

# Одна задача — агент сам выберет инструменты и решит её
python -m localmind run "прочитай README.md и посчитай в нём количество слов"

# Автономный режим: агент выполняет список целей из state/goals.md сам
cp examples/goals.md state/goals.md
python -m localmind auto

# Дать одну цель прямо из командной строки
python -m localmind auto "создай файл report.txt со списком файлов проекта"
```

### Навыки (самопрограммирование)

```bash
python -m localmind skills list                 # активные навыки
python -m localmind skills new "посчитать SHA-256 хэш файла"   # агент пишет навык
python -m localmind skills pending              # что ждёт одобрения
python -m localmind skills approve sha256_file.py   # активировать навык
```

В автономном режиме агент вызывает `create_skill` сам, когда ему не хватает
способности для выполнения цели.

### Память

```bash
python -m localmind memory stats
python -m localmind memory search "что я знаю о проекте"
python -m localmind memory add "Проект называется LocalMind"
```

### Медиа: изображения и видео (локально)

LocalMind умеет генерировать картинки и короткое видео **локально, на открытых
моделях**. Изображения — через сервер, совместимый с API AUTOMATIC1111 / SD.Next
(Stable Diffusion / SDXL). Видео — через локальный видео-бэкенд (обёртку над
ComfyUI со Stable Video Diffusion / AnimateDiff).

```bash
# поднимите локально, например, AUTOMATIC1111 с флагом --api (порт 7860)
python -m localmind media image "город будущего на закате, кинематографично" --count 2
python -m localmind media image "портрет" --negative "размытость, лишние пальцы"
python -m localmind media video "волны накатывают на берег" --seconds 2

# image-to-image: перерисовать существующее изображение (--strength: 0=почти без
# изменений, 1=полностью заново)
python -m localmind media img2img "сделай зимнюю ночь" --init state/media/img.png --strength 0.55

# inpainting: править только область под чёрно-белой маской
# (белое в маске — перерисовать, чёрное — оставить)
python -m localmind media inpaint "надеть красную шляпу" \
    --init state/media/img.png --mask state/media/mask.png --strength 0.75

# image-to-video: оживить одну сгенерированную картинку в ролик
# (Stable Video Diffusion через локальный видео-бэкенд)
python -m localmind media img2video "лёгкий ветер, качаются деревья" \
    --init state/media/img.png --seconds 2

# slideshow: собрать клип из нескольких сгенерированных картинок
# (локально, через Pillow — видео-бэкенд не нужен)
python -m localmind media slideshow --images state/media/a.png,state/media/b.png,state/media/c.png --fps 6

# upscale: увеличить разрешение картинки (ESRGAN/R-ESRGAN на SD-сервере)
python -m localmind media upscale --init state/media/img.png --scale 4

# upscale видео: покадрово увеличить GIF-клип и пересобрать его
python -m localmind media upscale_video --init state/media/clip.gif --scale 2
```

Типичный конвейер: сгенерировать кадр (`image`) → оживить его (`img2video`),
либо собрать несколько кадров в клип (`slideshow`).

Агент может вызывать всё это сам — инструменты `generate_image`,
`generate_video`, `image_to_image`, `inpaint_image`, `image_to_video`,
`images_to_video`, `upscale_image` и `upscale_video` доступны в `run`/`auto`.
Файлы сохраняются в `state/media/`
(внутри песочницы). Настройка адресов серверов — в секции `media` файла
`config.yaml`.

> Генерация идёт офлайн на ваших моделях — внешнего сервиса-«цензора» в этой
> цепочке нет. При этом LocalMind **не отключает и не обходит** защитные
> механизмы самих моделей: модуль лишь обращается к движку, который вы
> настроили. Ответственность за законность создаваемого контента (в частности,
> недопустимость изображений реальных людей без согласия и любого запрещённого
> законом материала) лежит на пользователе.

## Как устроен агент

```
                ┌──────────────── ReAct-цикл (agent.py) ────────────────┐
  задача ──▶    │  мысль → действие(инструмент) → наблюдение → …        │ ──▶ ответ
                └───────┬───────────────┬───────────────┬───────────────┘
                        │               │               │
                   LLMClient        ToolRegistry      Memory (RAG)
                   (llm.py)          (tools.py)        (memory.py)
                   Ollama, локально  файлы, код,       семантический
                                     shell, навыки     поиск по опыту
                                         │
                                   SkillManager (skill_manager.py)
                                   генерация → проверка (safety.py)
                                   → песочница → одобрение → новый инструмент
```

| Модуль | Назначение |
|---|---|
| `llm.py` | клиент Ollama на стандартной библиотеке (чат, стрим, эмбеддинги) |
| `memory.py` | долговременная память и обучение через RAG (семантика + лексический запас) |
| `tools.py` | инструменты: чтение/запись файлов, исполнение кода, память, shell |
| `safety.py` | песочница путей и фильтр разрушительного кода |
| `skill_manager.py` | самопрограммирование: агент пишет, проверяет и регистрирует навыки |
| `agent.py` | цикл рассуждение→действие на JSON-протоколе (работает с любой моделью) |
| `media.py` | локальная генерация медиа: txt2img, img2img, inpainting, image-to-video, слайдшоу, апскейл картинок и видео |
| `web.py` | браузерный интерфейс (чат + агент) на стандартной библиотеке; проксирует Ollama, поэтому CORS не нужен |
| `autonomy.py` | автономная работа по списку целей |
| `train.py` | опциональное дообучение весов через LoRA (нужен GPU) |
| `cli.py` | командный интерфейс |

## Дообучение под себя (опционально, нужен GPU)

RAG-память — это обучение «на лету» без изменения весов. Если нужно реально
адаптировать веса модели под ваши данные:

```bash
pip install -e ".[train]"          # torch, transformers, peft, datasets
python -m localmind.train --data state/train.jsonl --base Qwen/Qwen2.5-7B-Instruct
```

Датасет — JSONL: `{"instruction": "...", "input": "", "output": "..."}`.
Результат (LoRA-адаптер) далее сливается с базой и конвертируется в GGUF для
подключения в Ollama через `Modelfile`.
